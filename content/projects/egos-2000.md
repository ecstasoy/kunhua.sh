- **信号投递**：信号需在进程下次被调度时生效而非立即打断内核，为此以位掩码记录 pending 信号，并把投递挂在 `kernel_entry` 恢复上下文之前；投递时将 `mepc` 与 32 个寄存器存入进程的 `saved_signal_ctx`，改写 `mepc` 指向处理函数，把信号编号放入 `a0`、trampoline 地址放入 `ra`
- **用户态返回路径**：处理函数返回后需回到被中断的位置，而用户态无法直接恢复内核保存的上下文，为此在用户程序中放置一段 ***RISC-V*** 汇编 trampoline，向系统调用参数页写入 `SYS_SIGRETURN` 后 `ecall`，由内核完成恢复
- **默认处理与不可捕获信号**：`SIGKILL` 与默认处理不走上述路径，直接将 `mepc` 改写为程序的 exit 入口，使其无法被用户代码拦截
- **MLFQ 调度**：CPU 密集型进程会饿死交互型进程，为此按累计 CPU 时间三级降级（一个时间片内留高优先级、两个时间片内进中优先级、之后进低优先级），系统进程固定在高优先级队列，另设独立 sleep 队列
- **虚拟内存**：实现 ***Sv32*** 两级页表，`walk()` 按需分配 L2 页表页并返回 PTE 指针供直接修改权限位，切换后以 `sfence.vma` 刷新，另建立恒等映射区域
- **内存保护**：以 ***PMP*** 将 `0x80200000`–`0x80400000` 设为 ***NAPOT*** 区域并开放用户态 r/w/x，直接写 `pmpaddr0` 与 `pmpcfg0` 两个 CSR
- **用户级线程**：实现 TCB、FIFO 就绪队列与 `thread_create` / `thread_yield` / `thread_exit`；线程不能在自己的栈上释放自己，为此将回收延迟到下一次 create 或 yield
